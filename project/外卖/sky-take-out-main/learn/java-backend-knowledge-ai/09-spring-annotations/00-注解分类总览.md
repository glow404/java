# Spring 注解分类总览

## 1. 注解是什么

Java 注解（Annotation）本质上是附加在类、方法、字段或参数上的元数据。注解本身通常不直接执行代码，而是由 Spring、Spring Boot、编译器或其他框架在启动时、编译时或运行时读取，并据此改变程序行为。

例如：

```java
@Service
public class OrderServiceImpl implements OrderService {
}
```

`@Service` 不会替代 `new OrderServiceImpl()` 执行业务逻辑，它告诉 Spring：这个类应该被扫描并注册为容器中的 Bean。

## 2. 按作用分类

| 分类 | 代表注解 | 解决的问题 |
| --- | --- | --- |
| 启动与组件扫描 | `@SpringBootApplication`、`@ComponentScan` | 应用从哪里启动、扫描哪些类 |
| 容器与依赖注入 | `@Component`、`@Service`、`@Configuration`、`@Bean`、`@Autowired` | 对象如何创建、管理和组装 |
| 配置属性 | `@Value`、`@ConfigurationProperties` | 配置文件如何绑定到 Java 对象 |
| 条件装配 | `@ConditionalOnMissingBean` | 满足条件时才创建 Bean |
| Web 请求映射 | `@RestController`、`@RequestMapping`、`@GetMapping` | URL 如何找到 Controller 方法 |
| 请求参数绑定 | `@RequestBody`、`@RequestParam`、`@PathVariable` | HTTP 数据如何进入方法参数 |
| 异常处理 | `@RestControllerAdvice`、`@ExceptionHandler` | 异常如何统一转换为响应 |
| 事务与缓存 | `@Transactional`、`@EnableCaching`、`@Cacheable`、`@CacheEvict` | 事务和缓存逻辑如何声明式生效 |
| AOP | `@Aspect`、`@Pointcut`、`@Before` | 横切逻辑如何织入方法调用 |
| 定时与异步 | `@EnableScheduling`、`@Scheduled`、`@EnableAsync`、`@Async` | 定时任务和异步方法如何启用 |

## 3. 注解是怎样接入业务的

以一个 HTTP 请求为例：

```text
应用启动
  -> @SpringBootApplication 扫描组件和导入自动配置
  -> @Configuration / @Bean 创建基础设施 Bean
  -> @Autowired 注入依赖

收到请求
  -> @RequestMapping 找到 Controller 方法
  -> @RequestBody / @RequestParam 绑定参数
  -> @Transactional / @Cacheable 等代理逻辑生效
  -> 执行业务方法
  -> @RestControllerAdvice 处理未捕获异常
  -> @ResponseBody / @RestController 将返回值写成响应
```

很多功能依赖 Spring 代理。例如 `@Transactional`、`@Cacheable` 和 `@Async` 通常是由代理对象在目标方法前后插入额外逻辑。因此同一个类内部直接调用自己的方法，可能绕过代理，导致这些注解不生效。
