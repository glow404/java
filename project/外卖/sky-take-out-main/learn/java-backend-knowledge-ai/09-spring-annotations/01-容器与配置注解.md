# 容器与配置注解

## 1. `@Component` 与派生注解

### 1.1 `@Component`

`@Component` 表示一个普通 Spring 组件。组件扫描发现它后，会创建对象并注册到 IoC 容器。

```java
@Component
public class TokenValidator {
}
```

之后其他 Bean 可以注入它：

```java
@Autowired
private TokenValidator tokenValidator;
```

### 1.2 `@Service`、`@Repository`、`@Controller`

它们都是具有语义的组件注解，底层都属于 Spring 组件扫描体系：

| 注解 | 语义 |
| --- | --- |
| `@Service` | 业务服务层 |
| `@Repository` | 数据访问层 |
| `@Controller` | MVC 控制器 |
| `@RestController` | Controller + `@ResponseBody`，返回值默认写入响应体 |

项目中的 Service 例如：

```java
@Service
public class EmployeeServiceImpl implements EmployeeService {
}
```

Controller 使用：

```java
@RestController
@RequestMapping("/admin/employee")
public class EmployeeController {
}
```

启动时 Spring 扫描这些类，创建 Bean；Controller Bean 还会被 Spring MVC 用来建立 URL 到方法的映射。

## 2. `@Configuration` 与 `@Bean`

### 2.1 `@Configuration`

`@Configuration` 表示这是一个配置类。它通常集中声明框架需要的基础设施对象，而不是承载某个具体业务流程。

```java
@Configuration
public class PageHelperConfiguration {
}
```

### 2.2 `@Bean`

`@Bean` 标记的方法返回一个对象，Spring 会把这个返回值注册到容器中。方法参数也可以直接声明依赖，Spring 会自动注入：

```java
@Configuration
public class RedisConfiguration {

    @Bean
    public RedisTemplate redisTemplate(
            RedisConnectionFactory connectionFactory) {
        RedisTemplate redisTemplate = new RedisTemplate();
        redisTemplate.setConnectionFactory(connectionFactory);
        return redisTemplate;
    }
}
```

这里发生了三件事：

1. Spring 扫描 `RedisConfiguration`。
2. Spring 找到 `RedisConnectionFactory`，作为 `@Bean` 方法参数传入。
3. Spring 将方法返回的 `RedisTemplate` 注册为 Bean，业务 Controller 可以注入它。

```java
@Autowired
private RedisTemplate redisTemplate;
```

`@Bean` 适合第三方类或需要明确配置的对象；如果类本身可以添加组件注解，也可以使用 `@Component`、`@Service` 等方式注册。

## 3. `@Autowired`、`@Qualifier` 与 `@Primary`

### 3.1 `@Autowired`

`@Autowired` 按类型从容器中寻找依赖并注入：

```java
@Autowired
private EmployeeService employeeService;
```

项目的 `WebMvcConfiguration` 通过它注入两个 JWT 拦截器，然后在 `addInterceptors` 中注册到 Spring MVC。

### 3.2 多个同类型 Bean

如果容器中存在多个同类型 Bean，可以使用 `@Qualifier` 指定名称：

```java
@Autowired
@Qualifier("adminTokenValidator")
private TokenValidator validator;
```

也可以在其中一个 Bean 上使用 `@Primary`，把它设为默认候选者：

```java
@Bean
@Primary
public ObjectMapper defaultObjectMapper() {
    return new ObjectMapper();
}
```

当前项目没有在同一依赖类型上使用 `@Qualifier` 或 `@Primary`，但它们是解决 Bean 歧义的标准方式。

## 4. `@ConfigurationProperties` 与 `@Value`

### 4.1 `@ConfigurationProperties`

`@ConfigurationProperties` 将一组具有共同前缀的配置绑定到 Java Bean，适合配置项较多的场景：

```java
@Component
@ConfigurationProperties(prefix = "sky.alioss")
public class AliOssProperties {
    private String endpoint;
    private String accessKeyId;
    private String accessKeySecret;
    private String bucketName;
}
```

配置文件：

```yaml
sky:
  alioss:
    endpoint: oss-cn-beijing.aliyuncs.com
    bucket-name: example-bucket
```

Spring 会把配置值绑定到 `AliOssProperties`，然后 `OssConfiguration` 将它作为参数传给 `AliOssUtil` 的 `@Bean` 方法。

### 4.2 `@Value`

`@Value` 适合注入少量配置：

```java
@Value("${server.port}")
private int port;
```

简单规则可以使用 `@Value`；一组相关配置更适合使用 `@ConfigurationProperties`。

## 5. `@ConditionalOnMissingBean`

该注解表示：只有容器中不存在指定类型的 Bean 时，当前配置才生效。

项目中的 OSS 配置：

```java
@Configuration
public class OssConfiguration {

    @ConditionalOnMissingBean
    @Bean
    public AliOssUtil aliOssUtil(AliOssProperties properties) {
        return new AliOssUtil(
                properties.getEndpoint(),
                properties.getAccessKeyId(),
                properties.getAccessKeySecret(),
                properties.getBucketName());
    }
}
```

如果用户自己提供了一个 `AliOssUtil` Bean，Spring 就不会重复创建这里的默认 Bean。这种写法常见于 Spring Boot 自动配置，允许应用覆盖默认实现。

## 6. `@SpringBootApplication`

项目启动类使用：

```java
@SpringBootApplication
public class SkyApplication {
    public static void main(String[] args) {
        SpringApplication.run(SkyApplication.class, args);
    }
}
```

它是一个组合注解，主要包含：

```text
@SpringBootConfiguration   主配置类
@EnableAutoConfiguration  根据依赖和配置启用自动配置
@ComponentScan             扫描当前包及其子包中的组件
```

因为 `SkyApplication` 在 `com.sky` 根包下，所以 `com.sky.config`、`controller`、`service` 等子包都能被扫描到。
