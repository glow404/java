# 25 订单状态机与业务生命周期

## 1. 什么是状态机

订单不是简单的“有/无”数据，而是会按业务规则经历多个状态。状态机把允许的状态和转移动作明确下来，防止订单被随意修改。

## 2. 项目中的状态定义

代码位置：[`Orders.java`](../../../sky-pojo/src/main/java/com/sky/entity/Orders.java)

```java
public static final Integer PENDING_PAYMENT = 1;
public static final Integer TO_BE_CONFIRMED = 2;
public static final Integer CONFIRMED = 3;
public static final Integer DELIVERY_IN_PROGRESS = 4;
public static final Integer COMPLETED = 5;
public static final Integer CANCELLED = 6;
```

支付状态另有 `UN_PAID`、`PAID`、`REFUND`，说明订单状态和支付状态是两个不同维度。

## 3. 典型生命周期

```text
待支付 -> 待接单 -> 已接单 -> 派送中 -> 已完成
   │          │          │
   └──────────┴──────────┴──> 已取消
```

用户端和管理端订单 Controller 分别提供支付、取消、接单、拒单、派送、完成等动作，Service 负责修改状态和记录原因、时间。

## 4. 学习重点

- 状态字段是业务规则的核心，不应由客户端任意传入后直接保存。
- 每个动作都应校验当前状态是否允许转移。
- 订单状态、支付状态、配送状态应避免混成一个字段。
- 状态变化通常需要记录操作者、时间和原因，便于审计。
