# 27 微信支付回调

## 1. 为什么需要异步回调

支付请求发出后，客户端断网、页面关闭或网络延迟都可能导致客户端没有拿到最终结果。支付平台需要通过服务端回调通知商户，商户再以回调为准更新订单。

## 2. 项目中的代码

回调入口：[`PayNotifyController.java`](../../../sky-server/src/main/java/com/sky/controller/nofity/PayNotifyController.java)

```java
@RequestMapping("/notify/paySuccess")
public void paySuccessNotify(
        HttpServletRequest request,
        HttpServletResponse response) throws Exception {
    String body = readData(request);
    String plainText = decryptData(body);
    JSONObject jsonObject = JSON.parseObject(plainText);
    String outTradeNo = jsonObject.getString("out_trade_no");
    orderService.paySuccess(outTradeNo);
    responseToWeixin(response);
}
```

`decryptData` 使用微信支付 API v3 Key 和 AES-GCM 相关参数解密回调资源。

## 3. 回调处理链路

```text
微信支付平台
  -> POST /notify/paySuccess
  -> 读取原始请求体
  -> 解密 resource
  -> 取得商户订单号和交易号
  -> 更新订单支付状态
  -> 返回 SUCCESS
```

## 4. 生产环境必须考虑

- 校验平台签名和证书，而不能只依赖解密成功。
- 回调可能重复到达，`paySuccess` 必须幂等。
- 只有金额、商户号和订单号全部匹配时才能改状态。
- 处理成功后必须快速返回，耗时任务可异步化。
- API Key、私钥和证书不能提交到仓库。

当前项目还在支付接口中直接调用 `paySuccess` 来模拟支付成功，适合本地演示，但生产环境应以可靠的支付回调为最终依据。
