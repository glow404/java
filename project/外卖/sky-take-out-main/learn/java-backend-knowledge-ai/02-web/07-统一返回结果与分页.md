# 07 统一返回结果与分页

## 1. 统一返回的目的

如果每个接口返回格式都不同，前端需要为每个接口写不同的解析逻辑。项目在公共模块中定义了 `Result<T>` 和 `PageResult`，让接口返回格式保持一致。

## 2. `Result<T>`

代码位置：[`Result.java`](../../../sky-common/src/main/java/com/sky/result/Result.java)

```java
public class Result<T> {
    private Integer code;
    private String msg;
    private T data;
}
```

Controller 中通常这样返回：

```java
return Result.success(employeeLoginVO);
return Result.success();
return Result.error("业务失败原因");
```

## 3. `PageResult`

代码位置：[`PageResult.java`](../../../sky-common/src/main/java/com/sky/result/PageResult.java)

```java
public class PageResult {
    private long total;
    private List records;
}
```

分页接口一般形成两层结构：

```json
{
  "code": 1,
  "data": {
    "total": 100,
    "records": []
  }
}
```

## 4. 学习重点

- 泛型让 `Result<EmployeeLoginVO>`、`Result<OrderVO>` 保持类型信息。
- 统一包装解决了响应协议一致性问题。
- 分页结果至少需要当前页记录和总记录数。
- 统一响应不等于统一 HTTP 状态码；生产项目还应设计规范的状态码和错误码。

## 5. 学习练习

为一个列表接口定义明确的泛型返回类型，避免使用原始类型 `Result` 和原始 `List`，观察编译器能帮助你发现哪些问题。
