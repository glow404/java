# 09 全局异常处理

## 1. 为什么需要统一处理异常

业务失败可能发生在 Controller、Service 或 Mapper。让每个 Controller 都写 `try/catch` 会产生重复代码，还容易遗漏。全局异常处理器可以集中把异常转换为统一响应。

## 2. 项目中的代码

代码位置：[`GlobalExceptionHandler.java`](../../../sky-server/src/main/java/com/sky/handler/GlobalExceptionHandler.java)

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler
    public Result exceptionHandler(BaseException ex) {
        return Result.error(ex.getMessage());
    }
}
```

业务层可以直接抛出具体异常：

```java
throw new ShoppingCartBusinessException(
        MessageConstant.SHOPPING_CART_IS_NULL);
```

异常会向上冒泡，由 `@RestControllerAdvice` 统一接收。

## 3. 异常链路

```text
Service 发现业务不满足
  -> 抛出业务异常
  -> Spring 找到 @ExceptionHandler
  -> 转为 Result.error(...)
  -> 返回 JSON
```

项目还单独处理了 `SQLIntegrityConstraintViolationException`，将用户名重复等数据库约束错误转换为用户可理解的提示。

## 4. 学习重点

- 异常表示异常流程，不应把所有失败都用 `null` 返回。
- 异常类型应表达业务语义。
- 日志记录和返回给用户的消息应区分，不能把堆栈或敏感数据直接返回。
- 生产项目应补充未知异常处理、错误码、HTTP 状态码和统一日志追踪 ID。
