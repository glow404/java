# 20 密码处理与安全存储

## 1. 项目中的密码流程

管理员登录逻辑位于 [`EmployeeServiceImpl.java`](../../../sky-server/src/main/java/com/sky/service/impl/EmployeeServiceImpl.java)：

```java
password = DigestUtils.md5DigestAsHex(password.getBytes());
if (!password.equals(employee.getPassword())) {
    throw new PasswordErrorException(...);
}
```

新增员工时，项目将默认密码经过 MD5 后保存；修改密码时也会对新旧密码进行摘要处理。

## 2. 摘要和加密不是一回事

- 加密通常可以用密钥解密回原文。
- 密码哈希是单向的，验证时重新计算并比较哈希。
- MD5 速度太快，且容易受到彩虹表和暴力破解攻击，不适合生产密码存储。

## 3. 更合理的生产方案

使用 BCrypt 或 Argon2：

```text
注册/修改密码
  -> PasswordEncoder.encode(rawPassword)
  -> 保存带随机盐的结果

登录
  -> PasswordEncoder.matches(rawPassword, encodedPassword)
```

不应自己拼接固定盐，也不应把明文密码写入日志。登录 DTO 的日志尤其要避免输出密码字段。

## 4. 从项目可以学习的校验顺序

当前员工登录大致是：

```text
用户名查询不到 -> 账号不存在
密码不匹配     -> 密码错误
账号已禁用     -> 账号锁定
校验通过       -> 签发 JWT
```

这体现了 Service 层集中编排认证业务的方式。

## 5. 学习练习

保留接口行为不变，将 MD5 替换为 BCrypt，并编写测试验证：正确密码通过、错误密码失败、同一明文每次生成的哈希不同但仍能匹配。
