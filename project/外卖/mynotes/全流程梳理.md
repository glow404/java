按“请求从前端进来，到数据落库”的顺序走一遍，重点看 **`@Component` 类**和 **`@Bean` 产品**分别在哪一步起作用。

### 1. 前端发起请求

用户或管理员在浏览器 / 小程序里点击按钮，比如：

- 员工登录
- 新增菜品
- 上传图片
- 查看订单

请求先到 **Nginx**，再转发给 Spring Boot 后端。

### 2. Spring Boot 启动：先把所有图纸登记好

这一步还没有处理请求，只是准备“车间和生产线”。

Spring 启动时会扫描、解析、注册 `BeanDefinition`：

| 来源             | 例子                                | 变成什么 Bean       |
| ---------------- | ----------------------------------- | ------------------- |
| `@Component`     | `JwtTokenAdminInterceptor`          | 自己直接进容器      |
| `@Component`     | `JwtProperties`、`AliOssProperties` | 自己直接进容器      |
| `@Mapper`        | `EmployeeMapper`、`DishMapper`      | MyBatis 注册成 Bean |
| `@Configuration` | `OssConfiguration`                  | 配置类自己进容器    |
| `@Bean`          | `aliOssUtil()`                      | 方法返回值进容器    |

这里就是关键区别：

- **`@Component` 类 = 自己进容器的车间**
  Spring 直接 `new` 它。
- **`@Configuration` 类 = 配置车间**
  它自己也是 Bean。
- **`@Bean` 方法 = 配置车间里的生产线**
  生产线跑出来的返回值才是产品 Bean。

比如：

```java
@Component
public class JwtTokenAdminInterceptor implements HandlerInterceptor { ... }
```

它自己就是 Bean。

再比如：

```java
@Configuration
public class OssConfiguration {

    @Bean
    public AliOssUtil aliOssUtil(AliOssProperties properties) {
        return new AliOssUtil(
                properties.getEndpoint(),
                properties.getAccessKeyId(),
                properties.getAccessKeySecret(),
                properties.getBucketName()
        );
    }
}
```

这里会形成两张图纸：

1. `ossConfiguration`：`OssConfiguration` 自己的普通图纸；
2. `aliOssUtil`：工厂图纸，里面写着
   `factoryBeanName = ossConfiguration`
   `factoryMethodName = aliOssUtil`。

### 3. 请求进入：先经过拦截器

比如管理员登录后访问 `/admin/dish/page`。

请求到达 Spring MVC 时，会经过：

```java
JwtTokenAdminInterceptor
```

这个拦截器是 `@Component` 注册的，所以它本身就是一个 Bean。

它会做几件事：

1. 从请求头里取出 Token；
2. 用 `JwtUtil` 解析 JWT；
3. 解析出员工 ID；
4. 把员工 ID 放进 `ThreadLocal`；
5. 放行请求。

这里 `JwtProperties` 也是 `@Component` + `@ConfigurationProperties`，用来读取 `application.yml` 里的 JWT 配置。

### 4. 进入 Controller

拦截器放行后，请求到达 Controller，例如：

```java
@RestController
@RequestMapping("/admin/common")
public class CommonController {

    @Autowired
    private AliOssUtil aliOssUtil;

    @PostMapping("/upload")
    public Result<String> upload(MultipartFile file) {
        // 上传到阿里云 OSS
        String url = aliOssUtil.upload(bytes, objectName);
        return Result.success(url);
    }
}
```

这里注入的 `AliOssUtil` 不是 `@Component` 类，而是 `@Bean` 方法产生的产品。

### 5. 调用 `@Bean` 产品：第三方工具类

`AliOssUtil` 通常是阿里云 OSS SDK 的封装，属于第三方工具类，不能直接加 `@Component`。

所以它的进入方式是这样的：

```java
@Bean
public AliOssUtil aliOssUtil(AliOssProperties properties) {
    return new AliOssUtil(...);
}
```

流程是：

1. Spring 先确保宿主 Bean `ossConfiguration` 存在；
2. 调用 `ossConfiguration.aliOssUtil(properties)`；
3. 拿到返回的 `AliOssUtil` 对象；
4. 把它放进容器；
5. Controller 注入时，使用的就是这个对象。

这就是 `@Bean` 的典型作用：**把不能加 `@Component` 的第三方对象，通过方法返回值注册成 Spring Bean。**

### 6. 进入 Service：处理业务逻辑

Controller 再调用 Service，例如：

```java
@Service
public class DishServiceImpl implements DishService {

    @Autowired
    private DishMapper dishMapper;

    @Override
    @Transactional
    public void saveWithFlavor(DishDTO dishDTO) {
        // 保存菜品
        dishMapper.insert(dish);
        // 保存口味
        dishFlavorMapper.insertBatch(flavors);
    }
}
```

`DishServiceImpl` 上有 `@Service`，它属于 `@Component` 的派生注解，所以它也是直接进容器的 Bean。

### 7. 进入 Mapper：访问数据库

Service 调用 Mapper：

```java
@Mapper
public interface DishMapper {
    void insert(Dish dish);
}
```

`DishMapper` 不是普通 `@Component`，而是 MyBatis 扫描接口后注册成 Bean。它也可以理解成“被容器管理的对象”，但来源不是 `@Component`，而是 MyBatis 框架注册。

### 8. 缓存、定时任务、WebSocket 也会参与

如果请求的是菜品列表，可能会先查 Redis：

- 命中缓存：直接返回；
- 未命中：查 MySQL，再写回 Redis。

后台还会有：

- `Spring Task` 定时处理超时订单；
- `WebSocket` 推送来单提醒、催单提醒；
- AOP 切面自动填充创建人、修改人、时间等公共字段。

这些组件里，很多也是 `@Component` 注册的，比如切面、任务类、WebSocket 处理器。

### 全链路对比：`@Component` 和 `@Bean` 各在哪

| 环节       | 典型类                               | 注册方式                                  |
| ---------- | ------------------------------------ | ----------------------------------------- |
| 拦截器     | `JwtTokenAdminInterceptor`           | `@Component`                              |
| 配置属性   | `JwtProperties`、`AliOssProperties`  | `@Component` + `@ConfigurationProperties` |
| 配置类     | `OssConfiguration`                   | `@Configuration` 自己也是 Bean            |
| 第三方工具 | `AliOssUtil`                         | `@Bean` 方法返回值                        |
| 控制器     | `DishController`、`CommonController` | `@RestController`                         |
| 服务层     | `DishServiceImpl`                    | `@Service`                                |
| 数据层     | `DishMapper`                         | MyBatis `@Mapper`                         |
| 切面/任务  | `AutoFillAspect`、定时任务类         | `@Component` / `@Aspect`                  |

### 一句话收口

> **`@Component` 系列负责让“自己的类”直接进容器；`@Bean` 负责让“第三方对象”通过方法返回值进容器。苍穹外卖里，拦截器、Service、配置属性、切面多是 `@Component` 路线；而 `AliOssUtil` 这种第三方工具类，就是 `@Configuration` + `@Bean` 路线。**
