# 试用反馈实施与验收（2026-10-10）

范围来自用户提供的 question.md 八项试用反馈。当前 Git 根在上级 backend，项目仍为未跟踪工作；保留全部文件、数据库、源文件、审计和卷。当前五项 Compose 服务健康，沿用现有技术栈和界面，不提交或推送。

## 实施顺序

1. 增量迁移：显式行顺序、字段别名、已确认关联、表归档、结果显示偏好和异步助手运行；既有数据按来源行回填顺序，禁止清库。
2. 数据服务：原始顺序分页、别名解析及含糊澄清、表创建/查看/编辑/归档恢复；关联建议和预览确认后登记，双端权限及连接基数检查。
3. 助手工作流：先理解和解释下一步，保存待确认查询/变更/元数据计划；跟进修改或取消，异步可中止，确认仍绑定账号/会话/版本/范围和有效期。
4. 界面：重命名对话、等待时继续输入和中止按钮、全部表下拉与近期上下文、表管理和关联、隐藏/恢复页面结果但保留审计与快照。
5. 验证：真实 PostgreSQL 迁移及隔离 pytest，前端测试/类型检查/生产构建，Compose 健康检查，桌面与窄屏完整反馈流程；自动化模型明确为替身，部署后恢复原云渡配置。

## 验收标准

- 导入、查看、无显式排序查询和导出保留输入顺序；既有数据来源可确定时按源行排序，来源不完整时保留可复现顺序并记录限制。
- 别名只能指向已登记字段；模糊或重复别名必须澄清。助手先展示意图、范围、字段映射和口径，用户可确认、跟进调整或取消。
- 通过助手修改表/字段说明、单位与别名必须预览确认；不得把用户修改标为文件原文。
- 关联先展示匹配键、空键、重复键、连接基数和影响范围，经确认登记；任何一端越权、旧版本、不匹配类型/单位或危险重复汇总拒绝。不凭姓名自动关联。
- 对话名称在服务器保存，刷新重登恢复；助手请求在服务器保存运行状态，停止后不能产生可执行副作用，输入草稿保留。
- 手工创建/归档/恢复表均可核对和确认；归档保留源行、文件、已有结果及审计，并从当前可查询目录退出。
- 隐藏结果仅改变服务器显示偏好，两个结果展示位置同步隐藏；原结果和操作历史仍可查看，且可恢复。
- 两账号与匿名/CSRF校验覆盖新增资源。并发、重复确认、取消、过期和版本冲突不能绕过事务或扩大范围。

本轮失败、未执行项和实际结果记录到 FEEDBACK_TEST_REPORT.md；不将旧版验收自动视为新功能通过。
