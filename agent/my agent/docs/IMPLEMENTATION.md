## 分阶段实施

1. **契约与持久层**：定义 API，PostgreSQL 迁移，账号与服务端会话，归属校验，受控文件目录，审计与版本控制。
2. **文件导入**：xlsx/csv/docx/文本 PDF 解析、来源与合并范围记录、结构预览与人工修正，RQ 任务与幂等确认。
3. **查询与变更**：Pydantic 计划、SQLAlchemy Core 参数化编译、LangGraph 持久检查点、真实查询快照、事务式预览/确认/取消。
4. **前端工作台**：React/TypeScript/Vite/Ant Design/ECharts，目录首页、登录、导入核对、共享查询结果、可调宽侧栏、历史与导出。
5. **运行与验证**：Docker Compose、迁移、无默认密码管理员初始化、健康检查、pytest、前端测试及生产构建、浏览器流程、重建与独立备份恢复。

每阶段完成后执行对应检查。遇到失败修复后继续；未运行、失败、人工核对范围及测试替身必须在测试报告中如实区分。

## 验收标准

- 两个账号及匿名请求覆盖表、字段、文件、解析任务、会话、计划、结果、审计与下载隔离；Cookie 为 HttpOnly，身份仅来自服务端会话。
- 动态行采用 JSONB，字段 ID 来自注册表；查询有分页、上限、超时；禁止模型 SQL/代码执行。
- 真实文件标注验证明确垂直合并与范围外空值、多级表头、前导零、空成绩、公式缓存缺失、不同汇总粒度、缺失身份；不推断同名身份或自动向下填充。
- 导入必须核对后确认；重试/重复确认不重复建表。保存失败保留前端草稿。
- 真实数据库过滤、排序、分组、汇总及占比口径；缺少阈值/分母必须澄清；每个结果唯一快照，助手与工作台共用，切表后仍保留。
- 变更计划绑定用户、会话、表版本、目标及前后值和过期时间。冲突、过期、范围变化拒绝；重复确认仅一次；变更与审计同事务。
- 模型适配测试覆盖无效输出、超时、429、网络失败；未配置真实模型时界面清楚提示测试模式或未配置，不能声称真实联调。
- 容器重启/重建后账号、表、文件、对话、结果、审计与任务仍可恢复；备份实际恢复到独立测试数据库，禁止删除现有卷。
- Compose 包含前端、API、PostgreSQL、Redis、RQ worker 及健康检查，数据库无宿主端口；上传与数据库持久卷；密钥仅后端读取。
- README 包含可复现启动、管理员创建、迁移、停止、日志、备份恢复、HTTPS 及模型协议验证步骤。

## 明确的第一版边界

复杂扫描件/跨页表须人工核对，不能标注可靠解析。旧 xls 要求转换为 xlsx。综合评价的粒度拆分必须由用户确认，不能复制汇总数到明细中。未提供旧 D1，因此只提供迁移审阅方案，不执行线上迁移。
