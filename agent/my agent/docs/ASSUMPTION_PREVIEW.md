# 模糊口径建议与单位修复（2026-10-10）

## 本轮范围与实施

用户试用案例：`frr < 3%` 求最优 FAR 和对应阈值，补充小数比例、最小值及 unlock_threshold 后仍发生单位错误。保留数据、既有修改和安全确认机制，不自动修改字段单位。

1. 检查模型提示、字段注册表、单位校验、计划预览及相关测试，定位百分数表达与存储比例之间的差别。
2. 增加可持久保存的待确认假设，模型有依据时建议口径、列出依据和替代选项，先展示下一步，由用户确认或追问修改。未知字段、身份归属、缺少占比阈值/分母及缺乏依据的选择仍须澄清。
3. 规范百分数/小数比例转换，登记单位优先；单位缺失时只在待确认计划中声明存储解释，不能静默改写表资料或放过不兼容单位。
4. 最优值查询使用数据库受约束的极值筛选，保留并列最优记录及对应阈值，按分页上限展示，不能以普通最小值聚合丢失对应行。
5. 运行真实 PostgreSQL 回归、前端测试/生产构建、Compose 健康检查及虚构样例的真实模型验收。现有 admin 业务数据只用于只读元信息排查，不自动执行其查询或写入。

## 验收标准

- `3%` 在小数比例存储中编译为 `0.03`；百分数存储为 `3`。单位同义表达可规范化，不兼容的单位拒绝。
- 字段单位缺失时，候选口径有明确依据/替代选项并要求确认，元数据保持原样；用户明确补充的口径优先于历史候选。
- FAR 默认建议最小，多个阈值候选可同时展示，不能隐藏未经确认的选择。确认前没有查询结果。
- 极值必须在当前账号、所选表、过滤范围中由 PostgreSQL 计算；排除空极值，保留并列对应记录，重复确认共用快照。
- 新预览假设在助手及计划界面可读，刷新可恢复，追问可替换旧计划；旧接口遇到推断口径同样不能绕过确认。
- 实测与测试替身分别记录；失败及未执行项如实说明。

## FAR 缺失导致空结果的追查与修复

2026-10-10 用户最初提供的 `outputs/normal/.../far_frr_thresholds_0.50_0.85.csv` 共 36 行，满足 `frr < 0.03` 的有 14 行，unlock_threshold 从 0.50 到 0.63；整列 far 为空，impostor_total 全为 0。该文件本身无法计算 FAR。用户随后更正了文件；2026-10-11 核对实际数据库后，确认此前关于查询空结果的推断不适用于已保存快照，实际原因见下一节。

同一评估目录的 effective_config.yaml 设置 `max_impostor_identities_per_query: 0`，metrics.json 确认非本人尝试数为 0。原评估代码在此设置下关闭非本人比对，FAR 分母为 0 时返回 None。数据解决办法是沿用其余实际评估配置，将该参数设为 -1 开启全量非本人比对，使用新输出目录重新评估，再核对并导入新 CSV；正整数只抽样部分非本人身份，测量范围不同。未修改或重新执行上游评估，不能把缺失 FAR 填成 0。

Agent 查询保持空值与极值语义，在空极值结果时追加相同账号、表/已确认关联和过滤范围的统计，区分没有过滤匹配、指标全空及分页为空。说明和计数保存在 `extremum_diagnostic` 结果快照中；界面空表文案引导查看原因。新说明适用于重新执行的查询，历史结果按其保存快照展示。

本轮独立 PostgreSQL 全套 **178 项通过，无失败或跳过**（`test-results/empty-extremum-final-pytest.xml`），聚焦诊断与关联子集 **53 项通过**。覆盖全部为空的 min/max、真实 FAR=0、分页、账号/表与连接范围、确认快照重放。前端全套 **26 项通过**（串行、命令行 60 秒时限），TypeScript 校验及生产构建通过。Compose 已更新且全部运行服务健康；构建仍有原有的资源包大小提示，未增加依赖或数据库迁移。
