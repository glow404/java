## 验收环境与保护措施

- 确定性浏览器验收使用现有 Compose 的真实 API、PostgreSQL、Redis/RQ 和生产前端；**该组模型必须为明确的 mock 测试替身**，脚本先检查 `/api/ready`，真实模型配置时拒绝运行。真实云渡验收另用专用脚本，结果单独记录。
- 使用 `.env.acceptance` 中的专用测试账号；凭据、Cookie 和真实模型密钥不进入日志或报告。新增虚构样例均保留，不清空数据库、文件或卷。
- `scripts/e2e-feedback.cjs` 记录桌面与 390px 窄屏结果，输出到被忽略的 `test-results/`。脚本不会切换 Compose 模式，也不会自行重建服务。

## 验证边界

确定性模型替身用于完整工作流、错误与并发边界验证；真实云渡另外通过了上述两条别名查询及说明修改问题，证明这两条请求的 Responses 协议、结构化计划和预览/确认流程可用。没有据此声称任意中文问题、所有关联问题或全部计划类型均完成真实模型验收。超时、限流、无效输出和网络故障使用自动化替身覆盖，未主动制造真实服务商故障。

本版关联限两表 inner/left，数据版本改变需重新核对；没有来源的旧行无法推断原顺序。真实模型首条规划延迟较长，界面允许继续输入和中止，但目前没有降低服务商推理延迟的保证。生产构建有资源包大小警告；本轮未发布生产或调整共享权限。

## 浏览器验证中的修复

- Ant Design 单选文字覆盖搜索输入框时，直接点击 combobox 输入会等待超时；验收改用可访问键盘打开后选项点击。图标会进入按钮可访问名称，验收选择器改用按钮文字后缀匹配。
- 实际后台、数据库和界面前十二组通过后，发现测试替身把新的“将成绩字段说明改为……”完整请求拼接到上一条查询历史，错误地当作澄清回答。适配器已修复并补充两个禁止外网的回归测试；更新镜像后的完整浏览器复测已通过自然语言修改说明步骤。
- 关联管理中可能同时保留两个 Ant Design 下拉浮层；验收选项进一步通过 combobox 的 `aria-controls` 绑定当前浮层，避免同名表选项触发严格选择歧义。
- 窄屏长预览可正常滚动到确认按钮；验收先验证可点击性，再开始监听确认响应。分页抽屉的关闭名称受语言配置影响，验收绑定当前打开抽屉的关闭按钮。早期选择器失败不计为通过，最终完整流程重新执行后通过。

## 复现本轮验收

以下命令在项目根目录运行，要求前端已安装测试依赖、Edge 已安装、专用 `.env.acceptance` 已配置；不要把账号密码写进版本库。完整 E2E 必须由操作者显式启用 `compose.acceptance.yaml` 测试替身，若检测到真实模型会立即拒绝。

```powershell
$env:BROWSER_CHANNEL = 'msedge'
node scripts/e2e-feedback.cjs
$env:FEEDBACK_PERSISTENCE_STAGE = 'baseline'
node scripts/check-feedback-persistence.cjs
```

统一执行正常服务重启或容器重建并通过健康检查后，将 stage 分别设为 `service-restart`、`container-force-recreate` 再运行只读脚本；后者不要求模型替身，也不发送模型请求。不可执行带 `-v` 的卸载命令，所有验收样例均保留。

恢复 `.env` 中经验证且获许可的真实中转站配置后，可独立复现真实模型与快照界面检查；第一条命令可能产生服务商费用，第二条只读取已有结果：

```powershell
docker compose up -d --build --wait --wait-timeout 300
python scripts/verify-feedback-relay.py
$env:BROWSER_CHANNEL = 'msedge'
node scripts/check-feedback-relay-ui.cjs
```

备份/独立恢复复现命令见 README 的备份章节。两类恢复验收各使用一次新建恢复库，保留所有证据和环境；不要分享被忽略的会话、配置或备份文件。
